# 系统设计

## 一致性

签到事务只写入签到记录和Outbox事件。发布器异步投递RabbitMQ；积分消费者用事件ID唯一约束实现幂等，再更新积分余额。RabbitMQ不可用时Outbox保留事件并按退避策略重试。

## 幂等

Redis `SET NX`负责快速拦截十分钟内的重复请求，数据库 `(meeting_id,user_id)` 唯一约束承担最终一致的防重兜底。二维码和NFC只是不同入口，同一用户不能通过切换入口重复签到或重复获得积分。

## 入口令牌

二维码和NFC共用HMAC签名令牌，令牌包含会议ID、点位ID、过期时间和随机数。当前验证范围是令牌生成、解析、篡改检测和NFC入口类型处理，不包含支付宝真机碰触NFC。

## 限流

Redis Lua原子递增计数器分别限制用户和会议窗口请求，避免并发下的读改写竞争。
